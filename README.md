# Hero Siege Vision Farm Bot

Тестовая альфа-версия фармбота для Windows. Бот использует только захват
изображения окна и обычный ввод через Windows `SendInput`: чтения памяти,
DLL-инъекций и игровых хуков нет.

## Состояние альфа-версии

- Автокалибровка HUD и мини-карты.
- Исследование случайной карты по границе открытой области и FOW.
- Состояния исследования, боя, сбора лута, восстановления, смерти и перезапуска.
- WASD, удержание ЛКМ, навыки `Q/E`, зелья `1/2`.
- Аварийная остановка `Ctrl+Shift+F10`, пауза при потере фокуса и изменении окна.
- Dry-run, диагностический оверлей и журнал `events.jsonl`.
- Автоматические тесты калибровки, безопасности и управления.

Это технический preview. Реальная Windows-калибровка и 30-минутный прогон ещё
не выполнены. В репозитории нет проверенных шаблонов врагов, лута, смерти и
кнопки перезапуска; до их добавления программа намеренно отказывается запускать
автоматический ввод.

## Требования

- Windows 10/11 x64.
- Python 3.12 x64 с установленным `py launcher`.
- Hero Siege в безрамочном режиме.
- Доступ к физической клавиатуре для `Ctrl+Shift+F10`.

## Установка тестового релиза

1. Скачайте архив `hero-siege-bot-0.1.0a5-windows-test.zip` со страницы релиза.
2. Распакуйте его в отдельную папку.
3. Откройте PowerShell в этой папке.
4. Разрешите запуск локального скрипта только для текущего процесса и установите
   окружение:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\install_windows.ps1
```

Ручная установка из исходников:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
pytest -v
```

## Первый безопасный запуск

Запустите Hero Siege в безрамочном режиме, затем соберите кадры. Эта команда
вообще не создаёт модуль ввода:

```powershell
.\.venv\Scripts\python.exe scripts\collect_frames.py `
  --output-dir calibration-frames\first-run `
  --count 30
```

Проверьте PNG в `calibration-frames\first-run`. Подробная процедура разметки и
калибровки находится в `docs\calibration.md`.

## Обязательные шаблоны

Перед dry-run создайте каталог:

```powershell
New-Item -ItemType Directory -Force `
  src\hero_siege_bot\assets\templates
```

Добавьте четыре проверенных BGR/PNG-фрагмента:

```text
src/hero_siege_bot/assets/templates/
├── enemy.png
├── loot.png
├── death.png
└── restart.png
```

Шаблоны нужно вырезать из кадров той же версии игры и проверить на нескольких
последовательных кадрах. Не используйте непроверенный объект только потому, что
он визуально похож на врага или лут.

Все созданные пользователем файлы
`src\hero_siege_bot\assets\templates\*.png` — внешние данные: они не входят в
дистрибутив и не заменяются новым релизом. Это относится и к дополнительным
шаблонам, например `portal.png`. Перед распаковкой свежего Windows-релиза
сохраните все эти PNG отдельно, распакуйте релиз в новую папку, затем снова
добавьте их в каталог `assets\templates`. Не удаляйте старую установку, пока
шаблоны не перенесены.

Не копируйте в `0.1.0a5` изменённые файлы из `assets\anchors`: релиз содержит
свои калибровочные якоря, а при несовпадении строгих профилей использует
пропорциональную геометрию. Старые или ошибочные якоря могут заставить
template-first калибровку выбрать неверную геометрию.

После добавления шаблонов повторите editable-установку:

```powershell
.\.venv\Scripts\python.exe -m pip install -e .
```

## Dry-run без ввода

```powershell
.\.venv\Scripts\hero-siege-bot.exe dry-run `
  --config config\default.yaml
```

Проверьте рамки HUD, мини-карту, FOW, цели и предлагаемые действия. Персонаж не
должен двигаться или атаковать. Если распознавание ошибочно, не запускайте режим
с вводом.

Достижимая последовательность консольного вывода при пропорциональной
калибровке выглядит так:

```text
CALIBRATING
calibration: waiting for 3 stable frames (1/3)
calibration: waiting for 3 stable frames (2/3)
calibration: calibrated with proportional geometry
EXPLORING
```

Повторяющийся `CALIBRATING` не печатается на каждом кадре. Если состояние не
переходит в `EXPLORING`, оставьте окно игры неподвижным и активным минимум на три
кадра. Затем проверьте безрамочный режим, масштаб UI и диагностические PNG.
`PAUSED` означает потерю фокуса, окна или безопасной геометрии; верните фокус и
дождитесь новой калибровки. Сам вывод состояния не разрешает ввод: dry-run
по-прежнему использует только backend без ввода.

В `0.1.0a5` калибровка сначала строго проверяет профильные шаблоны-якоря.
Только если ни один профиль не принят, она может применить пропорциональную
геометрию по трём последовательным кадрам. Все три кадра должны быть в фокусе
и иметь одинаковые размеры изображения и client area; иначе ввод остаётся
заблокированным, а калибровка продолжает ожидание.

Одинаковый размер кадров сам по себе не подтверждает интерфейс Hero Siege.
Пропорциональная калибровка дополнительно требует независимые визуальные
признаки полос здоровья/ресурса слева сверху и структуры мини-карты справа
сверху. Пустой кадр или неподдерживаемый интерфейс отклоняется с сообщением
`proportional calibration rejected: unsupported HUD`. Порог строгой
калибровки нельзя настроить ниже `0.9`; небезопасные и нечисловые значения
конфигурации отклоняются.

Консоль печатает диагностические строки `calibration: ...` при изменении
причины или результата: прогресс сбора трёх кадров, нестабильный
фокус/геометрию, недоступный захват, потерю фокуса окна, изменение геометрии и
успешный метод (`template anchors` или `proportional geometry`). Эти сообщения
помогают отличить ожидание от успешной калибровки и не разрешают ввод сами по
себе.

Начиная с `0.1.0a4`, области полного кадра `gameplay` и `screen_state`
ограничиваются фактическими границами кадра после масштабирования профиля.
Диапазон автокалибровки по умолчанию расширен до масштаба `2.0`.
Мини-карта корректируется только при малом выходе через каждую границу — не
более 5% её ширины или высоты, что покрывает округление масштаба. Больший выход,
а также любая неверная область `health` или `resource`, по-прежнему переводит
наблюдение в безопасное состояние `PAUSED`. В таком случае сравните размеры
кадра и прямоугольники на диагностическом PNG; это признак несовместимого
масштаба UI или ложного совпадения якоря, а не повод ослаблять проверку.

## Тест с вводом

Перед запуском закройте лишние окна и держите пальцы на `Ctrl+Shift+F10`:

```powershell
.\.venv\Scripts\hero-siege-bot.exe run `
  --config config\default.yaml `
  --enable-input
```

`Ctrl+Shift+F10` блокирует дальнейшие действия и отпускает удерживаемые
клавиши/мышь.
Потеря фокуса, перемещение/изменение размера окна или потеря калибровки также
останавливают ввод и требуют повторной калибровки.

Полный порядок проверки подсистем описан в
`docs\windows-smoke-test.md`. Не начинайте 30-минутный тест, пока отдельно не
проверены `Ctrl+Shift+F10`, Alt+Tab, закрытие игры, движение, бой, навыки,
зелья, лут,
выход из застревания и смерть/перезапуск.

## Диагностика

По умолчанию данные сохраняются в `diagnostics`:

- `events.jsonl` — состояние, наблюдения и выбранные действия;
- PNG — диагностические кадры;
- оверлей — распознанные области и цели.

При ошибке приложите `events.jsonl`, проблемные PNG, разрешение окна, масштаб
Windows, масштаб UI и версию Hero Siege.

## Разметка скриншотов на Mac

Локальная страница правит YOLO-рамки в `datasets/user-screenshots/`.

```bash
.venv/bin/python -m hero_siege_bot.labeler_app
```

Откроется http://127.0.0.1:8765/ — старые рамки уже на кадре.

- `1`–`8` — класс (player, companion, enemy, loot, vein, chest, stash, waypoint)
- мышь — новая рамка или перетащить существующую
- `Delete` — удалить выбранную
- `←` `→` или `A` `D` — кадр, автосохранение в `labels/*.txt`
