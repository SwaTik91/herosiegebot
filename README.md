# Hero Siege Vision Farm Bot

Тестовая альфа-версия фармбота для Windows. Бот использует только захват
изображения окна и обычный ввод через Windows `SendInput`: чтения памяти,
DLL-инъекций и игровых хуков нет.

## Состояние альфа-версии

- Автокалибровка HUD и мини-карты.
- Исследование случайной карты по границе открытой области и FOW.
- Состояния исследования, боя, сбора лута, восстановления, смерти и перезапуска.
- WASD, удержание ЛКМ, навыки `Q/E`, зелья `1/2`.
- Аварийная остановка `Ctrl+Shift+F10`, пауза при потере фокуса и изменении окна.
- Dry-run, диагностический оверлей и журнал `events.jsonl`.
- 166 автоматических тестов.

Это технический preview. Реальная Windows-калибровка и 30-минутный прогон ещё
не выполнены. В репозитории нет проверенных шаблонов врагов, лута, смерти и
кнопки перезапуска; до их добавления программа намеренно отказывается запускать
автоматический ввод.

## Требования

- Windows 10/11 x64.
- Python 3.12 x64 с установленным `py launcher`.
- Hero Siege в безрамочном режиме.
- Доступ к физической клавиатуре для `Ctrl+Shift+F10`.

## Установка тестового релиза

1. Скачайте архив `hero-siege-bot-0.1.0a2-windows-test.zip` со страницы релиза.
2. Распакуйте его в отдельную папку.
3. Откройте PowerShell в этой папке.
4. Разрешите запуск локального скрипта только для текущего процесса и установите
   окружение:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\install_windows.ps1
```

Ручная установка из исходников:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
pytest -v
```

## Первый безопасный запуск

Запустите Hero Siege в безрамочном режиме, затем соберите кадры. Эта команда
вообще не создаёт модуль ввода:

```powershell
.\.venv\Scripts\python.exe scripts\collect_frames.py `
  --output-dir calibration-frames\first-run `
  --count 30
```

Проверьте PNG в `calibration-frames\first-run`. Подробная процедура разметки и
калибровки находится в `docs\calibration.md`.

## Обязательные шаблоны

Перед dry-run создайте каталог:

```powershell
New-Item -ItemType Directory -Force `
  src\hero_siege_bot\assets\templates
```

Добавьте четыре проверенных BGR/PNG-фрагмента:

```text
src/hero_siege_bot/assets/templates/
├── enemy.png
├── loot.png
├── death.png
└── restart.png
```

Шаблоны нужно вырезать из кадров той же версии игры и проверить на нескольких
последовательных кадрах. Не используйте непроверенный объект только потому, что
он визуально похож на врага или лут.

После добавления шаблонов повторите editable-установку:

```powershell
.\.venv\Scripts\python.exe -m pip install -e .
```

## Dry-run без ввода

```powershell
.\.venv\Scripts\hero-siege-bot.exe dry-run `
  --config config\default.yaml
```

Проверьте рамки HUD, мини-карту, FOW, цели и предлагаемые действия. Персонаж не
должен двигаться или атаковать. Если распознавание ошибочно, не запускайте режим
с вводом.

## Тест с вводом

Перед запуском закройте лишние окна и держите пальцы на `Ctrl+Shift+F10`:

```powershell
.\.venv\Scripts\hero-siege-bot.exe run `
  --config config\default.yaml `
  --enable-input
```

`Ctrl+Shift+F10` блокирует дальнейшие действия и отпускает удерживаемые
клавиши/мышь.
Потеря фокуса, перемещение/изменение размера окна или потеря калибровки также
останавливают ввод и требуют повторной калибровки.

Полный порядок проверки подсистем описан в
`docs\windows-smoke-test.md`. Не начинайте 30-минутный тест, пока отдельно не
проверены `Ctrl+Shift+F10`, Alt+Tab, закрытие игры, движение, бой, навыки,
зелья, лут,
выход из застревания и смерть/перезапуск.

## Диагностика

По умолчанию данные сохраняются в `diagnostics`:

- `events.jsonl` — состояние, наблюдения и выбранные действия;
- PNG — диагностические кадры;
- оверлей — распознанные области и цели.

При ошибке приложите `events.jsonl`, проблемные PNG, разрешение окна, масштаб
Windows, масштаб UI и версию Hero Siege.
